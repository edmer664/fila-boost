# Feature Specification: Filament Blueprint Agent Skill (Fila-boost)

**Feature Branch**: `001-filament-blueprint-skill`

**Created**: 2026-10-08

**Status**: Draft

**Input**: User description: "Fila-boost, an opensource alternative for filament-blueprint.Create a reusable agent skill that provides Filament blueprints directly through Laravel Boost. Define the core skill interface, tool definitions, and contextual prompt rules that guide AI coding agents to accurately generate working Filament resources, tables, and forms. Ensure the requirements focus on rapid iteration, clear trigger conditions, and fast verification so the agent reliably outputs valid, production-ready Filament code. Specify the exact input/output payloads and acceptance criteria needed for the skill to register cleanly and execute within the Boost MCP environment."

## Clarifications

### Session 2026-10-08
- Q: What target Filament version strategy should the Fila-boost agent skill enforce when generating and reviewing blueprints? → A: Strict Filament v5.x only (strictly adhere to v5 architecture with `Schemas/` and `Tables/` sub-namespaces).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Planning a Filament Feature via Agent Skill (Priority: P1)

As a developer using an AI coding agent with Laravel Boost, I want to trigger a specialized Filament blueprint planning skill that generates a comprehensive, unambiguous implementation blueprint for my desired administrative feature, so that an implementing agent has complete specifications (namespaces, schemas, tables, relationships, authorization, and tests) without needing to guess or make ungrounded architectural choices.

**Why this priority**: The fundamental purpose of Fila-boost is planning. Without an accurate, self-contained blueprint, implementing agents produce hallucinated methods, broken namespaces, and flawed component layouts.

**Independent Test**: Can be fully tested by invoking the planning skill in an agent environment with a feature prompt (e.g., "Build customer order management with line items and invoice generation"), verifying that the skill generates a structured Markdown blueprint containing exact model attributes, form components, table columns/actions, authorization rules, and test cases.

**Acceptance Scenarios**:

1. **Given** an AI agent connected to the Laravel Boost MCP server, **When** the developer asks the agent to plan a Filament feature using the blueprint skill, **Then** the agent activates the skill and produces a structured blueprint document in Markdown adhering to official Filament conventions.
2. **Given** a feature request with ambiguous business rules (e.g., payment status transitions), **When** the skill runs, **Then** it explicitly flags those unresolved business decisions at the top of the plan rather than silently guessing.
3. **Given** a blueprint generated by the skill, **When** inspected, **Then** it includes fully qualified class names, exact method signatures, component configurations, authorization policy definitions, and test criteria.

---

### User Story 2 - Boost MCP Skill Registration & Discovery (Priority: P2)

As a developer installing or updating the package in my Laravel application, I want the Filament blueprint skill to cleanly and automatically register within the Laravel Boost MCP environment, so that any supported AI coding agent (Claude Code, Cursor, Copilot, etc.) immediately discovers and loads the skill without manual tool configuration or environment friction.

**Why this priority**: Seamless integration with Laravel Boost's skill architecture is required for zero-friction adoption and workflow automation.

**Independent Test**: Can be tested by running the package registration / installer process within a Laravel project with Boost enabled, verifying that the blueprint skill files exist in the expected agent skills directory and the Boost MCP tool catalog exposes the skill triggers cleanly.

**Acceptance Scenarios**:

1. **Given** a Laravel application with `laravel/boost` installed, **When** Fila-boost is registered, **Then** the agent skill definition (`SKILL.md`) is accessible in the designated skills directory with valid YAML frontmatter (name, description, trigger conditions).
2. **Given** an AI agent inspecting available tools via MCP, **When** the tool catalog is retrieved, **Then** the blueprint tools are listed with valid JSON Schema parameter specifications and descriptive guidance.
3. **Given** an environment without proper setup or missing dependencies, **When** the skill is invoked, **Then** it provides clear, actionable diagnostics rather than failing silently.

---

### User Story 3 - Blueprint Implementation Review & Verification (Priority: P3)

As a developer or reviewer, I want an AI agent to evaluate an existing codebase checkout against a previously generated blueprint, verifying whether all specified resources, forms, tables, policies, and tests have been implemented correctly and conform to official Filament standards.

**Why this priority**: Completing the development loop requires fast verification; checking code against the spec prevents drift and verifies compliance before human review.

**Independent Test**: Can be tested by providing an existing application diff and the original blueprint markdown to the review tool/agent, verifying that it produces a granular compliance report highlighting fulfilled requirements, discrepancies, missing tests, or security concerns.

**Acceptance Scenarios**:

1. **Given** a generated blueprint and an application checkout where the feature has been coded, **When** the review skill is triggered, **Then** it systematically audits the implementation against each section of the blueprint (resources, form fields, table columns, actions, authorization, test coverage).
2. **Given** an implementation that introduces an unverified mass-assignment vulnerability or missing policy authorization, **When** the review skill evaluates the code, **Then** it flags the issue as a high-priority deviation from safe Filament defaults.

---

### Edge Cases

- **Complex Nested Relationships**: What happens when a resource requires deep multi-level relationship management (e.g., BelongsToMany with pivot form fields, or polymorphic relations)? The skill MUST specify explicit Filament relation managers or Repeater components with corresponding model cast and foreign key details.
- **Unsupported / Version Mismatch**: What happens when the target application runs an older or preview version of Filament (e.g., Filament v3 vs v4/v5)? The skill MUST detect or allow specifying the Filament version and adjust component names and method syntax accordingly.
- **Large Schemas Context Exceeded**: How does the system handle an extensive schema with dozens of models? The blueprint generator MUST support modular breakdown or clustered blueprints to prevent exceeding agent token limits.
- **Missing Application Database/Models**: What happens when the developer asks for a blueprint in a greenfield project where Eloquent models and migrations do not exist yet? The blueprint MUST include the necessary migration definitions, model casts, and relationships prior to the Filament resource specification.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The skill MUST be packaged as a free, open-source (MIT licensed) composer package compatible with Laravel 11+ and Filament v5.x.
- **FR-002**: The skill MUST provide a standardized `SKILL.md` file following the Agent Skills specification with valid YAML frontmatter (name, description, trigger keywords, and version).
- **FR-003**: The skill MUST expose a primary planning tool through Laravel Boost's MCP interface that accepts feature descriptions and generates a structured Markdown blueprint.
- **FR-004**: The planning prompt rules MUST instruct the agent to produce self-contained blueprints adhering strictly to Filament v5.x modular architecture, containing:
  - Exact namespaces and fully qualified class names.
  - Eloquent model attributes, casts, relationships, and enum definitions.
  - Resource configurations, cluster bindings, and navigation settings adhering to Filament v5 (`App\Filament\Resources\{Name}\{Name}Resource.php`).
  - Modular schema definitions (`App\Filament\Resources\{Name}\Schemas\{Name}Form.php`) with component types, validation rules, and reactive hooks.
  - Modular table definitions (`App\Filament\Resources\{Name}\Tables\{Name}Table.php`) with column types, filters, actions, and bulk actions.
  - Resource page classes (`Pages\List{Name}.php`, `Pages\Create{Name}.php`, `Pages\Edit{Name}.php`, `Pages\View{Name}.php`).
  - Plain-English authorization policy specifications.
  - Pest test scenarios covering resources, form submissions, and table actions.
- **FR-005**: The skill prompt rules MUST enforce lightweight, spec-first planning: generating actionable plans quickly without unnecessary bureaucratic overhead.
- **FR-006**: The tool definitions MUST declare strict, validated JSON Schemas for all input arguments and output results in compliance with the Model Context Protocol (MCP).
- **FR-007**: The system MUST provide an installation/registration mechanism that links the skill into the local agent skills directory recognized by Laravel Boost.
- **FR-008**: The skill MUST include verification rules ensuring all suggested Filament component APIs, method signatures, and render hooks match official Filament v5.x conventions.
- **FR-009**: The skill MUST enforce safe security defaults: mandatory authorization policies, scoped queries, tenant isolation awareness, and validation rules for all input components.
- **FR-010**: The skill MUST provide a reviewing capability to compare an existing application implementation against a saved blueprint, reporting discrepancies and missing tests.

### Key Entities

- **Blueprint**: A self-contained Markdown document representing the complete implementation plan for a Filament feature, including models, resources, forms, tables, policies, and test requirements.
- **Agent Skill Definition (`SKILL.md`)**: The standardized metadata, triggers, and instructional rules loaded on-demand by AI coding agents when planning or reviewing Filament features.
- **MCP Tool Definition**: The declarative schema and handler registered with Laravel Boost that exposes blueprint generation and verification capabilities to external AI agents.
- **Verification Report**: A structured audit comparing a codebase against a blueprint, detailing fulfilled criteria, discrepancies, and failed quality gates.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: An AI coding agent can generate a complete, syntactically correct Filament feature blueprint in under 60 seconds from a natural language request.
- **SC-002**: 100% of generated blueprints contain fully qualified namespaces, exact method names, and explicit validation rules, requiring 0 manual namespace corrections by the user.
- **SC-003**: Implementing agents provided with the generated blueprint produce code that passes Laravel Pint and Pest test execution on the first implementation attempt in at least 90% of benchmark scenarios.
- **SC-004**: Zero proprietary licensing friction: package installation and skill activation require only standard open-source package manager commands without license key requirements.
- **SC-005**: The skill footprint is lightweight, consuming minimal initial agent context window tokens until activated by relevant Filament planning triggers.

## Assumptions

- Target applications run on modern PHP (>= 8.2), Laravel (>= 11.x), and Filament v5.x.
- The hosting developer environment has `laravel/boost` (or an MCP-compatible client) installed and operational.
- AI coding agents interacting with the skill support the standard Model Context Protocol (MCP) and Agent Skills specification.
- Test suites in the target projects use Pest PHP (with PHPUnit compatibility).
- Code formatting follows standard Laravel Pint defaults.
